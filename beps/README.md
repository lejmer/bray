# Bray Enhancement Proposals

Bray Enhancement Proposals, or BEPs, describe substantial changes to Bray and record the reasons for design decisions.
They cover the language, official libraries and tooling, and project processes.

[BEP 1: The BEP process](bep-0001.md) defines the governance, proposal types, statuses, document requirements, and review rules.
The [submission guide](submit-a-bep.md) explains how to submit a proposal with the [BEP template](template.md).

Each BEP has one canonical discussion in the **BEPs** category of the
[official Bray repository's GitHub Discussions](https://github.com/lejmer/bray/discussions).
Pull requests submit and revise the Markdown documents.
The [discussion board reference](../docs/contributing/discussions.md) describes the categories and forms.

## Index

The index lists every admitted BEP.

| BEP | Title | Type | Status |
| --- | --- | --- | --- |
| [1](bep-0001.md) | The BEP process | Process | Draft |

Editors update the index when a proposal's number, title, type, or status changes.
BEP numbers are independent of GitHub issue, discussion, and pull request numbers.
Each BEP keeps its number after rejection, withdrawal, or supersession.

## Adoption

BEP 1 is the initial process proposal. Its Draft status means the BDFL has not yet adopted the process.
Adoption requires a decision in its canonical GitHub Discussion.
The decision identifies the approved revision and effective date.
The [adoption rules](bep-0001.md#validation-and-adoption) also cover shortened review.
