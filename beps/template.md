## Motivation and scope

## Proposal

For a Technical BEP, explain how users use the change.
Specify the syntax, semantics, interfaces, errors, edge cases, and interactions with existing features.
Include proposed changes to the language reference where relevant.
Define enough behavior for another implementer to implement the design without making new language decisions.

For a Process BEP, define the roles, procedures, exceptions, transition, and effective date.

For an Informational BEP, present the explanation or analysis.
Describe the evidence, conclusions, and limitations.
Put binding technical or process requirements in a Technical or Process BEP.

## Rationale and alternatives

## Impact

Describe the effects on users, implementations, official libraries and tooling, and project practices.
Address compatibility, migration, security, performance, and interoperability where relevant.
Follow Bray's applicable compatibility policy.

## Validation and adoption

Explain how to evaluate the proposal and put it into effect.

For a Technical BEP, describe the tests, prototype evidence, implementation work, and experimental availability.

For a Process BEP, describe the transition, responsible roles, and effective date.

For an Informational BEP, identify the intended audience.
Explain how reviewers can assess the evidence and conclusions before publication.
