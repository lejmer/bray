# Standard Library

Bray's standard library is the ordinary `std` package. It provides public modules for common data handling, memory, concurrency, I/O, platform services, interoperability, and testing. The package is explicit rather than ambient, and selected declarations receive compiler-recognized behavior only through stable declaration identity.

**General specifications:** [Standard-library declarations](https://github.com/lejmer/bray/blob/develop/docs/language/compiler-known-and-standard-library/standard-library-declarations.md), [standard-library recognition](https://github.com/lejmer/bray/blob/develop/docs/language/compiler-known-and-standard-library/standard-library-recognition.md), and [recognized operations](https://github.com/lejmer/bray/blob/develop/docs/language/compiler-known-and-standard-library/recognized-standard-library-operations.md)

For text output, pass string directly to print or print_line and handle their IoError result only when needed. Call `writer.write_all`, `reader.read_exact`, or their async methods to complete an entire borrowed byte range with exact failure progress. These are default trait methods over the individual partial-transfer operations. Buffered streams coalesce small writes, bypass empty buffers for transfers at least as large as their capacity, and flush only when requested. I/O that can block requires blocking_execution(). See [I/O and platform services][io-platform] for detailed transfer, synchronization, and cleanup rules.

Use `string` methods for text: `length`, `is_empty`, `get`, `slice`, `characters`, and `as_bytes`. Construct validated text with `string.from_utf8`. Characters provide `code_point`, `char.from_code_point`, `encode_utf8`, and Unicode classification methods. `encode_utf8` returns `std.character.Utf8Encoding`. Borrow its initialized bytes with `as_slice`.

Import `std.iteration.IteratorDefaultOperations` to use `first`, `nth`, `take`, `skip`, and `enumerate` as methods on any iterator. `OrderedSequence` supplies its search and sort algorithms as default members, and `std.numeric.Integer` supplies checked arithmetic from its required named `IntegerBounds` contract.

For shared mutable state, use `std.sync` guards or `std.atomic` operations. Synchronous waits require `blocking_execution()` and defer pending cancellation to the next checkpoint. Use `std.channel.bounded<T>` for cancellation-safe async transfer with explicit backpressure, including capacity-zero rendezvous.

Use `std.collection.Deque<T>` for owning double-ended storage with constant-time logical indexing and amortized constant-time pushes and pops at either end. Shared, mutable, and consuming iteration follows logical front-to-back order even when storage wraps. `std.collection.Stack<T>` and `std.collection.Queue<T>` are one-field adapters over `Deque<T>`; activate `StackDequeAdapter` or `QueueDequeAdapter` for their shared capacity and storage operations, project the deque explicitly with `as_deque` or `as_deque_mut`, and convert explicitly with `from_deque` and `into_deque`. See the [double-ended sequence surface](https://github.com/lejmer/bray/blob/develop/docs/design/core-data-standard-library.md#double-ended-sequence-surface) and [collection adapters](https://github.com/lejmer/bray/blob/develop/docs/design/core-data-standard-library.md#collection-adapters).

Use `std.collection.HashMap<Key, Value>` and `HashSet<Value>` for owning hash collections with borrowed lookup. Keys require `Hashable<StableHasher>` and `Equatable`, whose implementations must be imported when needed. Construct with an optional retained-entry capacity, use `reserve` for additional capacity, and handle `MemoryLayoutError` from allocating operations. Map `get`, `get_mut`, `contains_key`, `insert`, `remove`, `remove_entry`, and `entry` avoid key copies. Set `get`, `contains`, `insert`, `replace`, `remove`, and `take` store values without a dummy map payload. Shared and consuming iteration is available for both, mutable iteration only changes map values, and iteration order is unspecified. See the [hash collection surface](https://github.com/lejmer/bray/blob/develop/docs/design/core-data-standard-library.md#hash-collection-surface).

For C interoperability, use only the `std.ffi.c` wrapper selected by that wrapper's exact `target.c` property. Use its `*_exact` constructor for the already exact Bray scalar, `*_checked` for range-checked integer conversion, and `*_wrapping` only when wrapping is the intended policy. Use `OwnedNarrowString.from_bytes` for raw narrow units and `OwnedNarrowString.from_utf8` for UTF-8 text. Use `OwnedWideString.from_string` and `BorrowedWideString.to_string` for target-width wide text. Borrow owned C strings with `as_borrowed`, and observe raw storage with `as_bytes`, `as_bytes_with_nul`, `as_units`, or `as_units_with_nul`. Raw unit construction does not imply text encoding. See [foreign and platform interoperability](https://github.com/lejmer/bray/blob/develop/docs/design/foreign-and-platform-interoperability.md#c-interoperability) and [target profiles and properties](https://github.com/lejmer/bray/blob/develop/docs/language/targets-layout-abi-and-raw-memory/target-profiles-and-properties.md).

Open dynamic libraries with `DynamicLibrary.open`, resolve typed symbols through `library.symbol<T>(name)`, consume the owner with `close` for release, or use `into_handle` only to transfer native ownership. `DynamicSymbol<T>` remains borrowed from its library. See [foreign and platform interoperability](https://github.com/lejmer/bray/blob/develop/docs/design/foreign-and-platform-interoperability.md#dynamic-libraries-and-symbols).

Use `std.thread.start` and consume the returned owner with `join` or `cancel` for synchronous native-thread work. The owner retains transferred borrows until termination. `wake` publishes one coalescing token for the child to consume with `park`, and `set_current_name` reports invalid names, allocation failure, and platform failure separately. Use `std.thread.run` as the async bridge.

`std.platform` is an internal implementation module, not part of the public standard-library surface. The compiler-provided `core` namespace is also separate from `std`. Consult [compiler-known declarations](compiler-known.md) when a task concerns protected representations or compiler-provided operations rather than ordinary library APIs.

Internal allocation, owned-text, and character helpers are Bray declarations under `std.runtime`. Public code uses their owning `std.memory`, `std.string`, and `std.character` surfaces.

[io-platform]: https://github.com/lejmer/bray/blob/develop/docs/language/io-and-platform-services.md

**Remember:** Start with the module group that owns the operation and read its linked specification. A declaration's `std` spelling does not imply compiler recognition.
