# Target-specific operating-system modules

The standard library exposes low-level operating-system values only through exact target-gated modules:

- `std.os.windows` when `target.identity.SYSTEM == "windows"`,
- `std.os.linux` when `target.identity.SYSTEM == "linux"`,
- `std.os.darwin` when `target.identity.SYSTEM == "darwin"`.

There is no portable fallback declaration for a target-specific child module. Referring to a child module on another
target is a compile-time availability error. Portable APIs remain in their owning modules and do not re-export these raw
values.

`std.os.windows.Handle`, `std.os.linux.FileDescriptor`, and `std.os.darwin.FileDescriptor` are distinct transparent
value types. Equal integer representations do not make them interchangeable and do not imply ownership or transfer of an
operating-system resource. Owner types define acquisition, borrowing, transfer, duplication, and release separately.

Native constants are generated Bray declarations checked into the standard-library source tree. Their only input is
`standard-library/targets/os-constants.json`, which names a pinned SDK authority and revision for each system. Every
generated source records the complete input's SHA-256 digest. Compilation reads the generated Bray source and never
reads host headers, so native and cross-target builds use the same values.

Regenerate the declarations with `cargo xtask standard-library os-constants generate`. Standard-library verification
checks the generated bytes and fails when they differ from the pinned description.
