## Findings

- Owners carry initialized subvalues, dependencies, capabilities, and lifecycle obligations. Ordinary moves transfer them; copies require a copy contract. Shared borrows copy; mutable borrows move/reborrow rather than duplicate exclusive authority. [Ownership](../language/ownership-and-borrowing.md).
- `finalize` can fail/suspend and leaves the value initialized; `destruct` is synchronous, infallible, and consumes remaining parts. Scope capabilities use `enter`/`exit` and `with`; teardown is not interchangeable with Rust `Drop`. [Lifecycle](../language/lifecycle.md).
- No source lifetime parameters or `Send`/`Sync` marker design is prescribed: inferred dependency metadata preserves storage, capabilities, lifecycle duties, and open independent-run transfer requirements across generic interfaces. Structured thread owners may retain creating-run borrows; unscoped runs may not. [Dependency contracts](../language/ownership-and-borrowing/dependency-contracts.md).
- Static paths offer shared access, not movement or direct mutation; interior mutation requires a proven synchronization/atomic/single-assignment/scoped capability. Exact-thread borrows pin live tasks to that attachment. [Access paths](../language/ownership-and-borrowing/storage-and-access-paths.md).
- Dependency-anchored borrows do not prolong source storage. Moves/fields/returns must preserve all roots; product-static destinations cannot contain exact-thread dependencies. Raw code/data symbols carry provider roots, including attachment roots for TLS. [Boundaries](../language/ownership-and-borrowing/scope-exits-and-ownership-boundaries.md).
- Copy cannot allocate, fail, run user code, or acquire an external resource; an owning residency lease must be noncopyable with explicit duplication if needed. Raw-pointer/callable copy does not supply new ownership. [Copy contracts](../language/types/copy-contracts.md).
- No hidden callable captures: explicit state accompanies typed callable contracts. Contract preservation includes ABI, execution, ownership, caller obligations, and guarantees; trusted implementation does not imply a trusted public caller. [Callables](../language/callables/callable-types-and-values.md), [Trust](../language/callables/trusted-functions.md).
- Partial moves from a type with whole-value lifecycle need proven reinitialization before that lifecycle/whole-value use/end; do not assume arbitrary Rust-style take patterns are legal. [Partial moves](../language/ownership-and-borrowing/partial-moves.md).
- A finalizer error may establish completion through checked postconditions; otherwise normal ownership end must handle/transfer the unresolved owner. Abnormal cleanup attempts graceful finalization, records failure, then resolves synchronous fallback and remaining parts. Host/static teardown is an explicit terminal boundary, not an ordinary scope. [Finalization](../language/lifecycle/finalization.md), [Scope exits](../language/lifecycle/scope-exits-panics-and-cancellation.md).
- `with` exit runs on every entered-body exit, **before body-local destruction**, with the capability still live. Therefore do not blindly use `with` to release the last residency pin around locals whose disposal still invokes provider code. [With](../language/lifecycle/with-expressions.md).
- Construction cannot publish stable observable identity before completing. Partial construction unwinds only initialized parts. Replacement must restore an initialized destination before propagating old-value cleanup failure. [Construction](../language/lifecycle/construction.md), [Replacement](../language/lifecycle/partial-values-and-replacement.md).
- `pure` excludes even temporary mutation, allocation, synchronization, inactive-frame creation and cancellation observation; `total` requires normal termination including cleanup. Checked completion can omit only the whole-value graceful step, not backing/result/child obligations; `Result.Error` itself counts as normal completion for totality. [Guarantees](../language/contracts-and-trust/execution-guarantees.md).
- Trusted source bodies still undergo guarantee verification. `uses` grants exact internal capability; caller requirements and live witness guarantees remain separate, and mutation/transfer invalidation rules apply. Typed witness owners can establish validity once without repeating checks downstream. [Witnesses](../language/contracts-and-trust/trusted-witness-values.md), [Trust](../language/contracts-and-trust/trusted-implementation-capabilities.md).
- Trait views preserve the concrete subject's finalization/destruction. Traits may require them but implementations do not provide alternate finalizer/destructor bodies. Static cleanup uses dependency/domain precedence, not one universal global order. [Selection](../language/lifecycle/lifecycle-selection.md), [Ordering](../language/lifecycle/lifecycle-ordering.md).

## Static, memory and execution findings

- Static initialization is constant complete materialization; runtime acquisition belongs to ordinary explicit initialization/`Once`, not formation side effects. Static identity includes owning product instance and exact TLS attachment, never address/hash/link order. [Statics](../language/declarations/static-storage-declarations.md).
- One owner per static domain; acyclic dependency cleanup, deterministic structural tie order within each domain, domain precedence across products/attachments. Close entries, resolve external roots, clean exact-thread domains, clean product domains, drain incidents, then release infrastructure. Static-owned edges inside a fixed teardown set must not become waits on themselves. [Static cleanup](../language/declarations/static-storage-declarations.md#entry-closure-and-product-cleanup).
- Static access becomes unavailable before cleanup; cleanup retains direct authority over declared dependencies but cannot publish new roots, initialize new statics, or reopen entry. Foreign entry attaches before use; nesting reuses attachment; outer detach waits for pinned work and cleans on the same thread.
- `Uninit<T>` has exact layout but no fictitious `T` or lifecycle; initialized epochs must be consumed/destroyed once. `RawBuffer` owns its committed prefix. Anchored safe views require live authority proving validity, initialization, aliases, synchronization, stable movement and pending finalization. [Anchored memory](../language/targets-layout-abi-and-raw-memory/uninitialized-storage-and-anchored-borrows.md).
- Raw pointers supply no ordinary ownership or automatic safe access; foreign-produced pointers may nevertheless carry provider dependencies. `DynamicSymbol<T>` retains its library; callable conversion preserves ABI and provider roots. Code/data addresses need not share representation. [Foreign symbols](../language/targets-layout-abi-and-raw-memory/foreign-data-and-symbols.md).
- Synchronous roots establish blocking/compute/main execution; async main is cooperative and stays on main. Started children select compatible lanes; identity observation does not grant execution authority. Only root/lane contracts establish ambient execution predicates. [Requirements](../language/async-and-concurrency/execution-requirements.md).
- Generated source frames resolve lexical owners before terminal publication; host observes that final record and resolves the returned payload, without rediscovering source owners. Product shutdown follows run termination; services remain live through payload/static cleanup. [Roots](../language/async-and-concurrency/execution-roots-and-product-shutdown.md).
- Async selection is required by reachable start/async entry/host async cleanup, not synchronous reports or root observation. Libraries do not select runtime implementations; workers/lanes may initialize lazily. Algorithm budgets are not hard host-capacity authority. [Selection](../language/async-and-concurrency/entrypoints-and-runtime.md).
- Private role metadata validates declarations/ABI/target/contracts; spelling or implementation language grants no authority. Bootstrap TLS uses four target key operations; clear-before-destructor, exact-thread callback, no panic crossing ABI. Owned callback outcomes preserve one report handle. Mandatory incident sink works without scheduler. [Low-level runtime](../language/async-and-concurrency/low-level-runtime.md).

## Frames, admission and concurrency findings

- `Future<T>`/`Task<T>` are protected compiler-managed owners, not source-layout wrappers. Calling async captures state without executing/scheduling; direct await stays in the same run and needs no control block. Only `start` secures stable independent storage; no public pinning type or hidden lambda captures. [Frames](../language/async-and-concurrency/async-representation-and-storage.md).
- Mandatory cleanup capacity is secured **before each new local obligation**, survives moves/wrapping/completion proofs, and ends only with its last activation/outcome owner. Represented children keep their own allowances; aggregates admit only additional local needs. Recursive/erased live obligations need adequate individual capacity, not a fixed global emergency pool. Application finalizer allocations remain fallible. [Cleanup capacity](../language/async-and-concurrency/async-representation-and-storage.md#cleanup-capacity).
- Start acquisition failure panics before publication and cleans the inactive frame; after publication return its sole owner. Join/cancel invocation itself only constructs an inactive future. No detach, raw poll/wake or completion-test public task API. Fallible completed payloads prohibit normal implicit task cleanup; abnormal cleanup records and abandons them explicitly. [Start](../language/async-and-concurrency/starting-tasks.md), [Task ownership](../language/async-and-concurrency/task-handles-and-obligations.md).
- Structured scope cleanup first visits **every initialized nested task obligation** to broadcast cancellation without resuming/waiting/destruction; then performs lifecycle resolution. Erased/recursive frames must expose separate visitors and preserve initialized-state tracking. [Scope cleanup](../language/async-and-concurrency/structured-task-scope-exit.md).
- Cancellation is cooperative, idempotent, wake-aware and shielded during cleanup; request is not completion. Finalizer errors become quiesced typed owned incidents; cancellation stays payload-free, so terminal observation transfers incidents to mandatory sink. A panic report owns its suppressed entries. [Cancellation](../language/async-and-concurrency/cancellation.md).
- Start and observed terminal cleanup create visibility edges; moving a task or requesting cancellation does not. Affinity carries an exact attachment or typed lane class, not a boolean; either track per-control-state dependencies or conservatively pin whole task. [Memory model](../language/async-and-concurrency/cross-run-memory-model.md), [Transfers](../language/async-and-concurrency/capability-transfer-across-run-boundaries.md).

## Questions to resolve

- Which obligations can typed owners and dependency-anchored borrows express directly? Which erased/foreign transfers need a private runtime protocol?
- What formation/static/bootstrap cycles must be broken with raw target mechanisms rather than higher-level library entry?
- Which fairness/registry/retention policies are required behavior, and which are existing implementation choices?
- Normative conflict candidate: static declarations/root shutdown say **any external root reaching storage or code prevents cleanup and unload**; BRA-501 permits static cleanup while escaped report/code owners remain. This is stronger than an unload-only requirement. Do not silently preserve that behavior or destroy reachable storage; propose an explicit semantic decision after consumer tracing.
- Minor wording conflict: low-level bootstrap says reverse registered TLS cleanup; static specification requires dependency-topological order with structural ties. Treat static semantics as controlling and check actual consumer requirements.

## Ordinary primitives and representation boundaries

- `box[S] T` uses an ordinary storage policy; borrowing must be pure/total, so lock acquisition belongs outside storage projection. Stable backing can be owned without a public pin type. Trait views retain concrete lifecycle and witness dependencies, cannot downcast, and cannot dispatch generic members. [Storage/view forms](../language/types/type-forms.md#owned-indirection-type-form).
- `RawAllocation` is linear authority, not three pointer/size fields; `RawBuffer` tracks initialized prefixes and supports ownership relocation without element copies. Raw representation copies are not safe owner duplication. Allocation failure is a catchable panic; invalid layout is typed. [Allocation](../language/targets-layout-abi-and-raw-memory/raw-allocation-and-buffers.md).
- `Atomic<T>` is protected, target-conditional and never secretly lock-backed. Order is closed and operation-specific; notify is advisory, wait must recheck. Safe ordinary sync owners supply authority and visibility. Spin/mutex ticket fairness, writer-priority RwLock, ordered channel/budget waiters are actual specified policies; internal runtime queues have no implied identical policy. [Atomics](../language/async-and-concurrency/atomic-operation-contracts.md), [Library concurrency](../language/async-and-concurrency/standard-library-concurrency.md).
- Public thread owners are ordinary Bray types; public `start` can fail creation/capacity, owns explicit state, and supports structured borrows. Internal worker entry must bootstrap attachment/run state before it can use public thread/run facilities. Public thread cleanup cannot own async-finalized payloads; async bridge can. OS waits are not cancellation points unless the wrapper declares them.
- Contracts are flow-sensitive; mutation/epoch/finalization can invalidate witnesses. Mathematical contract arithmetic never wraps. Trusted obligations must be proved or propagated through every wrapper/lifecycle/ABI boundary. [Reasoning](../language/contracts-and-trust/contract-reasoning.md), [Obligations](../language/contracts-and-trust/obligation-propagation.md).
- Default data/call ABI is compiler-defined; only explicit layout and `c`/`system` ABI cross native boundaries. Protected frames/reports, borrows, boxes and views need explicit private lowering, not representation casts. Target-gated Bray contributions can implement OS leaves directly. [ABI](../language/targets-layout-abi-and-raw-memory/callable-abi.md), [FFI](../language/targets-layout-abi-and-raw-memory/extern-declarations-and-ffi.md).
- Panic snapshots mutable/borrowed messages before raising; failed snapshot raises allocation panic instead, never silently truncates. Report forwarding transfers the same owner; synchronous report destruction owns suppressed payload destruction. [Panic](../language/expressions/panic-expressions.md), [Run outcomes](../language/types/union-types.md).
- Runtime callback state is explicit; retained registration must stop new calls and drain entered calls before freeing context. Foreign trampolines acquire product entry/attachment before access and contain abnormal outcomes, returning ABI-zero. [Callbacks](../language/targets-layout-abi-and-raw-memory/extern-declarations-and-ffi.md#foreign-callbacks).
- Libraries expose portable contracts but choose no scheduler. Test roots share one activation's statics; serial exclusion is command-wide; cleanup failure belongs to product. Runtime/platform modules can stay internal ordinary Bray; no new compiler-known source package is needed. [Products](../language/modules-and-packages/package-products-and-source-graphs.md), [Tests](../language/modules-and-packages/test-products-and-entries.md).
- Existing normative collections give owned ordered sequences/maps without Rust collection policies; ordered maps preserve structural traversal, hash iteration cannot define cleanup order. I/O uses typed failures and explicit guard boundaries; process context immutable startup snapshot; time/entropy nondeterminism explicit. Temporal provider remains a separate permitted exception. [Core data](../language/core-data-standard-library.md), [Platform services](../language/io-and-platform-services.md).
