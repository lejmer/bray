# Runtime consumers and behavior inventory

Baseline: `a65cc2f0`, research branch `docs/bray-native-runtime-design-research`. This round starts only after the language notes are complete. Rust is a caller/removal inventory and behavior reference, not an architectural prescription. All paths below will be verified from actual consumers.

## Research checkpoint

- Both research rounds complete for host/admission design. See the design proposal for decisions and proof cuts. These are source-tracing findings, not newly executed test results.
- Required coverage: generated executable/library/test entry; product/thread statics; provider load/retirement; reports and typed errors; mandatory admission; task/frame/cancellation/wakes; workers/root shutdown; platform leaves and packaging.

## Consumer inventory

- **Product formation and closure:** generated descriptor supplies closed static callbacks/order/dependencies and required services; formation validates once, secures per-static cleanup capacity, then opens entry. Entry/root/attachment acquisition serializes with closure. Foreign nesting reuses exact-thread state. Cleanup callbacks and provider callbacks execute outside host lock; worker detachment/join must not hold it. [Formation](../../crates/bray-runtime/src/product/host/formation.rs), [Control](../../crates/bray-runtime/src/product/host/operations.rs).
- **Current host mechanism:** process `OnceLock<Mutex<BTreeMap<load, host>>>`, TLS `RefCell` maps, counters and optional retained scheduler. These are representations, not consumer requirements. Immutable closed metadata and compiler-provided cleanup order could remove duplicate maps/sorts in Bray. [Model](../../crates/bray-runtime/src/product/host/model.rs).
- **Static cleanup:** synchronous product requires no selected scheduler; async finalizers admit a task before publishing static obligation. Generated owner disposal discharges source allowance; failed formation rolls it back. Static errors/panics are retained and all eligible cleanups continue. Current fixed arrays (8/4/3 incidents) are callback bridge bounds, not universal capacity for arbitrary nested obligations. [Cleanup](../../crates/bray-runtime/src/product/cleanup.rs).
- **Exact-thread attachment:** current foreign path deliberately initializes Rust TLS registries/platform callbacks before scope-owning TLS, avoiding exit-order invalidation. Required behavior is attach-before-access, nested ownership, exact-thread cleanup once and quiescence before unload; Rust TLS initialization ordering is removable machinery. [Attachment](../../crates/bray-runtime/src/product/attachment.rs).
- **Provider semantics conflict confirmed:** explicit unit test `synchronous_formation_closes_statics_without_waiting_for_code_owners` preserves BRA-501's split. Host quiescence omits `provider_roots`; `RETIRE` later waits for them with an off-lock acquisition revision check. Spec currently blocks cleanup for external code roots too. Design must select semantics explicitly and revise affected fixtures accordingly.
- **Bray already owns report storage/chain operations:** bootstrap implements panic/message ownership, outgoing record transfer, pooled slots and consumption. It still calls Rust `substrate_initialization/shutdown`; existing `@copy` ABI records contain ownership words that require trusted transfer discipline. Reuse behavior and target bindings, not necessarily scalar-word representation. [Bootstrap](../../runtime/bootstrap/src/bootstrap.bray), [Records](../../runtime/bootstrap/src/records.bray), [Pool](../../runtime/bootstrap/src/record-pool.bray).
- **Resource admission pool:** current Bray spin-locked slab/free-list secures outgoing source credits before publication. Pool/slab bookkeeping is optimization, whereas conservation across source/activation/report transfer and no cleanup-time allocation are mandatory. Its linked-image lifetime is not proof of unloadable host ownership; map consumers next.
- **Generated consumers:** product planner derives roles/services from reachability; host MIR forms product before root, drives/observes/resolves outcome, then static cleanup/report drain/shutdown. Export trampoline acquires entry before body and releases after outcome resolution, returning zero on denied entry. Compiler may inline trivial synchronous root; it must not inline a policy runtime into generated IR merely to label it native. [Host planner](../../crates/bray-compilation/src/compilation/product/codegen/host.rs), [Host lowering](../../crates/bray-codegen-llvm/src/translation/unit/effect/host.rs), [Callback](../../crates/bray-codegen-llvm/src/translation/unit/callback.rs).
- **Source outgoing consumers:** MIR admits/discharges per concrete local lifecycle; structural aggregate forwarding charges no duplicate child allowance. Current planner counts nontrivial finalize/destroy/broadcast calls and omits synchronous total unit calls. LLVM activates a record around cleanup, retires it into pending panic report, and preserves returned provider ownership. This covers outgoing slots, **not proof of secured async activation/frame/completion storage**. [Capacity planning](../../crates/bray-compilation/src/compilation/product/realization/outgoing.rs), [Lowering](../../crates/bray-codegen-llvm/src/translation/unit/outgoing.rs).
- **Run/report bridge:** Rust callback boundary admits two bridge records before thread state; reentrant native entry isolates/restores run/task cancellation and output context. Bray report consumer takes/clears one handle, releases backing before provider, consumes release-generated reports before later entries. Current rendering still calls Rust substrate. Required: no native unwind, same report owner forwarded, no cleanup-time reacquisition, disposal after producer-thread exit. [Boundary](../../crates/bray-runtime/src/native/callback.rs), [Consumer](../../runtime/bootstrap/src/report-consumer.bray).
- **Typed incidents:** retain concrete type/source/ordinal and provider-backed destruction callback; terminal abnormal path quiesces payload, abandons graceful finalization, destroys once, preserves destructor-generated panic. Rust `Any + Send`, downcasts and reserved Rust panic backing are bridging mechanisms to remove when linked Rust disappears. [Incident](../../crates/bray-runtime/src/incident.rs), [Frame reports](../../crates/bray-runtime/src/frame.rs).
- **Frame adapter concern:** current Rust adapter builds descriptors/state vectors/symbol strings and `Arc<Mutex<terminal>>`; result backing allocates on resume and only supports alignment up to `u128`. These are inventoried hazards for capacity/layout work, not a verified compiler rejection or failing test. New native activation must use checked layout and previously admitted storage. [Adapter](../../crates/bray-runtime/src/native/frame.rs).
- **Activation consumer:** awaited and cleanup children maintain parent/frame/outcome/retired storage until result disposal; current `NativeRun` duplicates descriptors and heap-allocates activation wrappers. Requirement is direct-await composition in one run with dependencies/lane affinity retained and storage live through all retired users. A ready-task transition budget of 64 is an implementation policy. [Run](../../crates/bray-runtime/src/native/run.rs).
- **Task consumer:** start reserves identity/records, accepts inactive frame, installs cancellation/control/waiters, registers compatible lane, publishes runnable owner. One concurrent resume, one terminal payload observation, callbacks outside task lock. Current Arc/Mutex/maps/weak wake closures are not source contracts. [Task](../../crates/bray-runtime/src/task/implementation.rs), [Execution](../../crates/bray-runtime/src/native/state/execution.rs).
- **Wait/cancellation consumer:** observe/register/recheck prevents lost wake; withdrawal removes an uncommitted waiter; signal callbacks run outside lock; generation exhaustion closes rather than reuses stale identity. Request remains observable through nested shields; completion alone authorizes dependent disposal. Native event can be signalled by a thread without runtime attachment, so foreign-facing resolution remains necessary. [Event](../../crates/bray-runtime/src/event.rs), [Native event](../../crates/bray-runtime/src/native/event.rs), [Cancellation](../../crates/bray-runtime/src/cancellation.rs).
- **Scheduler/worker consumer:** main/origin/compatible lane routing, coalesced wakes, wake-during-resume handling, timers, diagnostics and task limit enforcement. Current duplicated task registries/descriptor graphs, eager three-worker launch and grow-on-blocking-worker strategy are choices. Product close requests cleanup on each attached worker and waits for acknowledgement; worker stop/join follows statics. Cleanup requests currently allocate, so terminal reserve must cover them too. [Scheduler](../../crates/bray-runtime/src/scheduler/engine.rs), [Workers](../../crates/bray-runtime/src/native/workers.rs).
- **Capacity semantic mismatch to reconcile:** spec hard task limits bound executing lanes and queue excess ready tasks; current native allocation caps registered task count (`tasks.len`) and can fail at that limit. Distinguish storage admission failure from execution quota; do not inherit the Rust limit interpretation. [Limits](../../crates/bray-runtime/src/scheduler/contract.rs).
- **Existing Bray thread/sync building blocks:** native thread state/result/guard owners, `Uninit<T>`, structured observation, ticket locks, Once rollback and anchored views already exist in source. Public thread/run wrappers still depend on private runtime boundary/identity/event roles. Runtime workers must use lower-level target thread creation to avoid bootstrapping through their own scheduler. [Thread boundary](../../standard-library/std/src/thread/boundary.bray), [Operations](../../standard-library/std/src/thread/operations.bray), [Sync](../../standard-library/std/src/sync/once.bray).
- **Confirmed cleanup-time payload allocation:** generated static finalizer error path allocates backing before copying the error into an incident; on failure it cleans that error rather than preserving the original typed incident. This must be replaced by admitted error/result storage to satisfy mandatory capacity, not just ported to Bray. [Finalizer lowering](../../crates/bray-codegen-llvm/src/mapping/static_storage/finalization.rs).
- **Target leaves exist in Bray:** POSIX thread create/join/TLS-key operations, Windows counterparts, atomic waits, heap and virtual-memory bindings, dynamic loader wrappers and clock services reach explicit system ABI declarations. Runtime-linked Rust `bray-platform` still contributes its own thread identity, event/clock/memory and `mio`/mapping implementation. Reuse existing target leaves below public wrappers. [POSIX](../../standard-library/std/src/thread/unix.bray), [Heap](../../standard-library/std/src/platform/heap/unix.bray), [Platform crate](../../crates/bray-platform/Cargo.toml).
- **Test-host consumer:** linked adapter reads commands, capture/output context, cancellation control/timeouts, source-anchored result reporting and finish protocol. Compiler/tooling coordinator can remain Rust outside produced programs; child-side session/codec/transport/capture must become Bray. Command-wide serial scheduling and shared test-product statics need end-to-end evidence, not just porting callbacks. [Session](../../crates/bray-runtime-adapter/src/test_host/session.rs), [Adapter](../../crates/bray-runtime-adapter/src/test_entry.rs).
- **Packaging still links Rust:** xtask builds Rust adapter host/callback/scheduler/cancellation/event/test-host archives, partitions common support, then adds two Bray archives. Role symbols alone cannot prove language provenance. Need archive-member/link-map provenance with zero reachable Rust support per replaced consumer, then remove partitioning/common support when all consumers migrate. [Artifact command](../../xtask/src/runtime_artifact/command.rs), [Symbol audit](../../xtask/src/native_symbols.rs).
- **Existing conformance evidence to preserve:** native audit loads two copies, checks independent bindings/statics/TLS, generated C trampolines, direct and reusable archive/imported-MIR formation, retained reports/errors after producer-thread exit, unload/reload and deterministic artifacts. Its code-only closure expectation needs correction under the recommended spec semantics. [Audit](../../xtask/src/readiness/native_execution/static_storage.rs), [C consumer](../../xtask/fixtures/native-execution/static_storage_host.c).
- **Source role support evidence:** compiler tests bind real Bray functions to canonical roles and retain static atomic backing; existing runtime manifests emit interface/MIR/archive for six native targets. Source-level owner/atomic/Uninit/sync implementations exist. This supports writing the host now; it does not prove new admission descriptors, hidden owner allowances or full dependency inference without compilation proof. [Codegen tests](../../crates/bray-compilation/src/compilation/product/codegen/implementation.rs), [Bootstrap manifest](../../runtime/bootstrap/bray-package.json).

## Requirement versus mechanism ledger

| Required behavior | Current mechanism to reconsider | Native proof consumer |
| --- | --- | --- |
| Admit before publication; preserve input on rejection | Scalar source credits and separate adapter allocations | Nested/erased/partial/static owners under forced allocation rejection |
| Entry closure and full dependency-safe teardown | Global host/TLS maps, code roots excluded from quiescence | Two loaded providers; escaped owner blocks cleanup; internal static edge does not self-wait |
| Exactly-once callback/result/report disposal | Rust guards, `Any`, descriptor clones and terminal Arc | Destructor-generated panic, release on another allowed thread, last callback return before unload |
| Stable frames and ordered broadcast/resolution | Box/Pin/activation trees and duplicate descriptor graph | Direct await without child task; recursive/erased cleanup with allocator denied |
| Race-safe cancellation, wake and completion | Weak registrations and closure objects | Register/signal/cancel races; wake while running; single observer and visibility |
| Compatible lane progress and bounded execution | Eager worker pool; task-count quota | Async main pinned, exact attachment, queued excess ready tasks, blocking/compute isolation |
| Zero project-owned linked Rust | Partitioned adapters/common/platform archives | Per-member provenance and map audit for executable, shared/archive/MIR, async and test products |

## Open implementation proofs

- Can role-bound bootstrap code use typed noncopy owners/borrows without recursive ordinary foreign-entry wrapping or self-admitting its own cleanup? Specify exact private-role handling before source implementation; never exempt ordinary source by spelling.
- Does compiled dependency metadata distinguish all provider/static/attachment roots through erasure and incident callbacks? Cross-product dynamic teardown-set closure is normative; current single-product counter path does not by itself prove it.
- Inventory inspected required contracts, principal callers and representative fixtures. Not every Rust helper or platform binding was read; no new builds or performance measurements were run. These bounded compiler/runtime gaps belong to native proof cuts, not a justification for expanding the Rust runtime first.
- Existing design documents agree on Bray policy/private ABI separation but explicitly retain Rust activation owners and code-only retention in `cleanup-storage-and-reports.md`; those statements need replacement if this proposal is accepted. Current native-shim allowances also need tightening to the user's all-Bray destination. [Cleanup design](../design/cleanup-storage-and-reports.md), [Runtime design](../design/async-runtime.md), [Platform design](../design/io-and-platform-services.md).
