# Appendix B. Runtime implementation inventory

This appendix supports the [WIP native runtime design](bray-native-runtime-design.md#appendix-b-implementation-inventory). It records current consumers, behavior, fixtures and implementations to replace. The inventory includes provider formation work proposed in BRA-501. Recheck those mechanisms against develop when implementing each consumer. Its findings come from source tracing and existing fixtures, without new execution or performance measurements.

The inventory covers executable, library and test entry, product and thread statics, providers, reports, typed errors, cleanup admission, frames, tasks, cancellation, wakes, workers, shutdown, platform bindings and packaging. It identifies principal callers and representative fixtures rather than every helper or binding.

Required behavior follows Bray's language contracts and the WIP design. Rust data structures identify current mechanisms, not a required representation for their replacements. The [cost analysis](bray-native-runtime-cost-analysis.md) supports representation choices. Performance gates follow the design's [evidence requirements](bray-native-runtime-design.md#performance-requirements-and-evidence).

## Product hosts and generated callers

- The generated product descriptor supplies static callbacks, cleanup order, dependencies and required services. Formation validates the binding, secures each static's cleanup capacity and opens entry. Entry, root and attachment acquisition serialize with closure. Nested foreign entry reuses exact-thread state. Callbacks, worker detachment and worker join must run outside the host lock. [Formation](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/product/host/operations.rs), [Control](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/product/host/operations.rs).
- The current host uses a process-wide `OnceLock<Mutex<BTreeMap<load, host>>>`, TLS `RefCell` maps, counters and an optional retained scheduler. Consumers require host identity and synchronized transitions. Immutable metadata and compiler-provided cleanup order may remove duplicate maps and sorting. [Model](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/product/host/model.rs).
- Synchronous products need no selected scheduler. Async static finalizers admit a task before publishing the obligation. Generated disposal discharges the source allowance, and failed formation rolls it back. Cleanup retains errors and panics while continuing eligible work. Fixed incident arrays of 8, 4 and 3 entries bound callback bridges. They do not establish capacity for arbitrary nested obligations. [Cleanup](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/product/cleanup.rs).
- Foreign attachment currently initializes Rust TLS registries and platform callbacks before scope-owning TLS to preserve exit order. Consumers require attachment before access, nested ownership, exact-thread cleanup once and quiescence before unload. A Bray implementation can replace the Rust TLS ordering mechanism. [Attachment](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/product/attachment.rs).
- The proposed BRA-501 test `synchronous_formation_closes_statics_without_waiting_for_code_owners` checks a lifetime split between code and statics. Host quiescence excludes `provider_roots`. Later `RETIRE` waits for them and checks an acquisition revision outside the lock. The specification also blocks static cleanup for external code roots. The [provider lifetime design](bray-native-runtime-design.md#provider-lifetime) requires whole-product retention and updates to these fixtures.
- The product planner selects roles and services from reachability. Generated host MIR forms the product, runs and observes the root, resolves its outcome, cleans statics, drains reports and shuts down. Export trampolines acquire entry before the body, release after outcome resolution and return zero if entry closes. The compiler may inline a trivial synchronous root. Runtime policy still belongs in Bray source. [Host planner](https://github.com/lejmer/bray/blob/develop/crates/bray-compilation/src/compilation/product/codegen/host.rs), [Host lowering](https://github.com/lejmer/bray/blob/develop/crates/bray-codegen-llvm/src/translation/unit/effect/host.rs), [Callback](https://github.com/lejmer/bray/blob/develop/crates/bray-codegen-llvm/src/translation/unit/callback.rs).
- MIR admits and discharges capacity for each concrete local lifecycle. Aggregate forwarding does not charge child allowances twice. The planner counts nontrivial finalization, destruction and broadcast calls and omits synchronous total unit calls. LLVM activates a record around cleanup, retires it into a pending panic report and preserves returned provider ownership. This path covers outgoing-slot behavior. Async activation, frame and completion storage still need evidence. [Capacity planning](https://github.com/lejmer/bray/blob/develop/crates/bray-compilation/src/compilation/product/realization/outgoing.rs), [Lowering](https://github.com/lejmer/bray/blob/develop/crates/bray-codegen-llvm/src/translation/unit/outgoing.rs).

## Reports and cleanup backing

- Bray bootstrap code already implements panic and message ownership, outgoing transfer, pooled slots, report consumption and chains. It still calls Rust `substrate_initialization/shutdown`. Existing `@copy` ABI records encode ownership in words and depend on trusted transfer discipline. Preserve the behavior and useful target bindings when choosing typed owners. [Bootstrap](https://github.com/lejmer/bray/blob/develop/runtime/bootstrap/src/bootstrap.bray), [Records](https://github.com/lejmer/bray/blob/develop/runtime/bootstrap/src/records.bray), [Pool](https://github.com/lejmer/bray/blob/develop/runtime/bootstrap/src/record_pool.bray).
- The Bray spin-locked slab and free list secure outgoing source credits before publication. Mandatory behavior includes ownership conservation through source, activation and report transfers, with no allocation during mandatory cleanup. Pooling is an optimization. An image-local pool does not establish safe ownership across unloadable hosts.
- The Rust callback boundary admits two bridge records before acquiring thread state. Reentrant entry isolates and restores run, cancellation and output context. The Bray report consumer takes and clears one handle, releases backing before the provider and consumes release-generated reports before later entries. Rendering still calls Rust support. The replacement must prevent native unwind, forward the same owner and avoid reacquisition during cleanup. Disposal after producer-thread exit must respect dependencies. [Boundary](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/native/callback.rs), [Consumer](https://github.com/lejmer/bray/blob/develop/runtime/bootstrap/src/report_consumer.bray).
- Typed incidents retain concrete type, source, ordinal and a provider-backed destruction callback. Abnormal terminal handling quiesces the payload, abandons graceful finalization, destroys it once and preserves destructor-generated panic. Linked Rust `Any + Send`, downcasts and reserved Rust panic backing need removal. [Incident](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/incident.rs), [Frame reports](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/frame.rs).
- Generated static finalizer error handling allocates backing before copying the error into an incident. If allocation fails, it cleans the error and loses the original typed incident. The replacement needs admitted error and result storage. Translating this path into Bray would preserve the defect. [Finalizer lowering](https://github.com/lejmer/bray/blob/develop/crates/bray-codegen-llvm/src/mapping/static_storage/finalization.rs).

## Frames, tasks and scheduler behavior

- The Rust frame adapter constructs descriptors, state vectors, symbol strings and `Arc<Mutex<terminal>>`. Result backing allocates during resume and supports alignment only up to `u128`. These source findings identify capacity and layout work. They are not results from a new failing test. Native activation needs checked layout and previously admitted backing. [Adapter](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/native/frame.rs).
- Awaited and cleanup children retain parent, frame, outcome and retired storage until result disposal. `NativeRun` duplicates descriptors and allocates activation wrappers. The replacement must compose direct await within one run, preserve dependencies and lane affinity, and retain storage through its last retired user. The ready-task transition budget of 64 is an implementation choice. [Run](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/native/run.rs).
- Start reserves identity and records, accepts the inactive frame, installs cancellation state and waiters, registers a compatible lane and publishes the runnable owner. A task permits one concurrent resume and one terminal payload observation. Callbacks run outside its lock. The current `Arc`, mutex, map and weak wake-closure representation can change. [Task](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/task/implementation.rs), [Execution](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/native/state/execution.rs).
- Observe, register and recheck prevent lost wakes. Withdrawal removes an uncommitted waiter. Signal callbacks run outside the lock. Generation exhaustion closes identity rather than reusing it. Cancellation requests remain observable through nested shields. Only completion permits dependent disposal. Native events can receive signals from unattached threads, so foreign handle validation remains necessary. [Event](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/event.rs), [Native event](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/native/event.rs), [Cancellation](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/cancellation.rs).
- Scheduler consumers need compatible lane routing, coalesced wakes, wake-during-resume handling, timers, diagnostics and limits. Duplicate registries, eager launch of three workers and growth when workers block are current choices. Product closure requests cleanup on attached workers and waits for acknowledgement before stopping and joining them. Those requests currently allocate. Mandatory terminal backing must cover them. [Scheduler](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/scheduler/engine.rs), [Workers](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/native/workers.rs).
- The specification limits simultaneous execution and queues excess ready tasks. Native allocation currently caps registered task count through `tasks.len` and can fail at that limit. The [execution limit design](bray-native-runtime-design.md#execution-limits-and-queues) separates task storage admission from the execution quota. [Limits](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime/src/scheduler/contract.rs).

## Existing Bray code, platform and packaging

- Bray already implements thread state, result and guard owners, `Uninit<T>`, structured observation, ticket locks, `Once` rollback and anchored views. Public thread and run wrappers still depend on compiler-validated boundary, identity and event roles. Runtime workers need lower-level target thread creation to establish their own scheduler prerequisites. [Thread boundary](https://github.com/lejmer/bray/blob/develop/standard-library/std/src/thread/boundary.bray), [Operations](https://github.com/lejmer/bray/blob/develop/standard-library/std/src/thread/operations.bray), [Sync](https://github.com/lejmer/bray/blob/develop/standard-library/std/src/sync/once.bray).
- Bray has POSIX and Windows thread creation, join and TLS-key bindings, atomic waits, heap and virtual-memory bindings, dynamic loading and clocks. These use explicit system ABI declarations. Linked Rust `bray-platform` still supplies thread identity, events, clocks, memory, `mio` and memory mapping. Reuse the existing Bray target bindings below public wrappers. [POSIX](https://github.com/lejmer/bray/blob/develop/standard-library/std/src/thread/unix.bray), [Heap](https://github.com/lejmer/bray/blob/develop/standard-library/std/src/platform/heap/unix.bray), [Platform crate](https://github.com/lejmer/bray/blob/develop/crates/bray-platform/Cargo.toml).
- The linked test adapter implements commands, captured output context, cancellation, timeouts, source-anchored reporting and the finish protocol. Compiler and tooling coordination can remain Rust outside produced programs. Child-side session, codec, transport and capture need Bray implementations. End-to-end fixtures must prove command-wide serial scheduling and shared test-product statics. [Session](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime-adapter/src/test_host/session.rs), [Adapter](https://github.com/lejmer/bray/blob/develop/crates/bray-runtime-adapter/src/test_entry.rs).
- `xtask` builds Rust host, callback, scheduler, cancellation, event and test-host archives, partitions common support and adds two Bray archives. Role symbol names cannot prove implementation language. Archive-member and link-map evidence must show zero reachable Rust support for each replaced consumer. Once all consumers migrate, remove the partitioning and common support. [Artifact command](https://github.com/lejmer/bray/blob/develop/xtask/src/runtime_artifact/command.rs), [Symbol audit](https://github.com/lejmer/bray/blob/develop/xtask/src/native_symbols.rs).
- Existing native audits load two copies and check independent bindings, statics and TLS. They exercise generated C trampolines, direct formation, archive and imported-MIR contributions, escaped reports and errors after producer-thread exit, unloading, reloading and deterministic artifacts. Preserve this coverage. The provider lifetime design requires changing the code-only closure expectation. [Audit](https://github.com/lejmer/bray/blob/develop/xtask/src/readiness/native_execution/static_storage.rs), [C consumer](https://github.com/lejmer/bray/blob/develop/xtask/fixtures/native-execution/static_storage_host.c).
- Compiler tests bind real Bray functions to defined runtime roles and retain static atomic backing. Runtime manifests emit interfaces, MIR and archives for six native targets. These fixtures cover Bray runtime-role bindings. New admission descriptors, inferred dependencies and allowances carried by hidden owners still need native compilation evidence. [Codegen tests](https://github.com/lejmer/bray/blob/develop/crates/bray-compilation/src/compilation/product/codegen/implementation.rs), [Bootstrap manifest](https://github.com/lejmer/bray/blob/develop/runtime/bootstrap/bray-package.json).

## Required behavior and current mechanisms

| Required behavior | Current mechanism to reconsider | Consumer that must prove the replacement |
| --- | --- | --- |
| Admit before publication and preserve inputs on rejection | Scalar source credits and separate adapter allocations | Nested, erased, partial and static owners under forced allocation rejection |
| Close entry and respect dependencies during teardown | Global host and TLS maps, with code roots excluded from quiescence | Two loaded providers where an escaped owner blocks cleanup and internal static edges allow cleanup to progress |
| Dispose callbacks, results and reports exactly once | Rust guards, `Any`, descriptor clones and terminal `Arc` | Destructor-generated panic, disposal on another permitted thread and last callback return before unload |
| Keep frames stable and separate broadcast from resolution | `Box`, `Pin`, activation trees and duplicate descriptors | Direct await without a child task, plus recursive and erased cleanup with allocation denied |
| Preserve cancellation, wake and completion under races | Weak registrations and closure objects | Registration, signal and cancellation races, wake during resume, single observation and visibility |
| Make progress on compatible lanes and bound execution | Eager worker pool and registered-task quota | Async main, exact-thread affinity, excess ready tasks queuing and blocking versus compute isolation |
| Link zero project-owned Rust | Partitioned adapter, common-support and platform archives | Member and map audits for executable, shared-library, archive, MIR, async and test products |

## Migration verification requirements

| Area | Required implementation evidence |
| --- | --- |
| [Host shutdown](bray-native-runtime-design.md#shutdown-ownership-and-lifecycle) | Blocked shutdown preserves caller ownership. Normal finalization uses existing execution guarantees. Abnormal abandonment retains resident cleanup, storage, reporting and compatible execution. Exact-thread cleanup remains possible without a destructor creating a new obligation. |
| [Provider lifetime](bray-native-runtime-design.md#provider-lifetime) | Repeated reload releases plugin resources while independently owned diagnostic history remains. Provider-dependent payloads prevent cleanup. Existing formatting or report operations are checked before introducing a dedicated conversion API. |
| [Bootstrap](bray-native-runtime-design.md#bootstrap-and-thread-attachment) | Typed host ownership, compiler-role lowering and TLS destructor entry use target bindings and explicit storage. Entry does not recursively wrap its own prerequisite, and admission does not depend on the service being formed. |
| [Static cleanup](bray-native-runtime-design.md#static-cleanup-order) | Product and thread-local cleanup use dependency order and deterministic structural ties. Thread-local cleanup stays on its attachment thread. |
| [Cleanup backing](bray-native-runtime-design.md#cleanup-storage-and-admission) | Size, alignment and transfer lifetime remain valid with allocation denied. Typed incident and result preservation use secured backing. Existing child allowances are not charged again. |
| [Tasks and waits](bray-native-runtime-design.md#frames-and-task-ownership) | One result transfer, retained dispatch and notification targets, direct await without another task record, cancellation withdrawal, callbacks outside collection locks and wakes during execution. |
| [Authority](bray-native-runtime-design.md#accessibility-and-runtime-authority) | Internal acknowledgement cannot authorize copied fields without witness guarantees, invalidating mutation, duplicate result transfer or stale storage use. Callable, callback and lifecycle wrappers preserve unchecked caller requirements. |
| [Execution limits](bray-native-runtime-design.md#execution-limits-and-queues) | Excess ready tasks queue and suspension releases an execution slot. Admitted backing remains live. Algorithm budgets remain distinct from execution limits. |
| [Component selection](bray-native-runtime-design.md#component-selection-and-binary-size) | Consumers omitting optional services omit their code and data. Registrations and descriptors do not retain unused implementations. Member and link-map audits establish the implementation language. |

Compiled dependency metadata must preserve provider, static and attachment roots through erased storage and incident callbacks. Current single-product counters do not establish teardown across dynamically connected products. Native provider consumers must cover that boundary.

Compiler and runtime gaps are resolved through the consumers in the implementation sequence. Conflicting design and language text is tracked in the WIP's [documentation integration](bray-native-runtime-design.md#documentation-integration) section.
